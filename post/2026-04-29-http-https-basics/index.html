HTTPS & HTTP 기초

2026-04-29·3분 읽기
#HTTP#HTTPS#TLS#네트워크#면접

HTTP를 한 줄로 정리하면

클라이언트와 서버가 데이터를 주고받는 약속(프로토콜)

근데 HTTP는 무상태(Stateless) 라 매 요청이 독립적이고 서버가 이전 요청을 기억 못한다.

클라이언트: "나 00이야, 로그인했어"
서버:       "...누구세요?" ← 기억 못함

그래서 쿠키/세션/JWT 같은 게 필요하다. 나중에 따로 정리하도록 하겠다.

HTTPS = HTTP + 암호화

HTTPS는 HTTP에 TLS 를 얹은 것.

→ TLS(Transport Layer Security) 란: 데이터를 암호화해서 주고받기 위한 보안 프로토콜, HTTPS에서 HTTP위에 얹히는 암호화 레이어가 TLS. 브라우저 주소창 위에 자물쇠 아이콘이 뜨는것이 TLS연결이 됐다는 뜻임

  • HTTP → 데이터가 평문으로 이동. 중간에서 누가 보면 다 보임.
  • HTTPS → 암호화해서 이동하니까 중간에서 봐도 해독 불가.

배포 환경에서 HTTPS가 아니면 브라우저가 경고를 띄우거나 카메라, 위치 같은 API를 막아버린다는 걸 실무에서 처음 알았다. 쿠키의 Secure 속성도 HTTPS에서만 제대로 동작하고.

로컬 http://localhost는 괜찮은데 실 배포는 무조건 HTTPS여야 하는 이유가 여기 있었다.

TLS 핸드셰이크 흐름

면접에서 "HTTPS 동작 방식 설명해보세요" 라고 물어보면 이 흐름으로 정리하면 될 것 같다.

1. 클라이언트 → 서버    "나 이런 암호화 방식 지원해"
2. 서버 → 클라이언트    "그럼 이걸로 하자, 내 인증서야"
3. 클라이언트           인증서 검증 (이 서버 믿을 수 있는 CA인지 확인)
4. 클라이언트 → 서버    암호화 키 교환
5. 이후 통신            암호화된 데이터 주고받기

net::ERR_CERT_AUTHORITY_INVALID 에러가 저 3번에서 인증서 검증이 실패한 거였다. 로컬에서 self-signed 인증서 쓸 때 맨날 만나던 에러인데 이제야 이해됐다.

HTTP 요청/응답 구조

Network 탭 열면 매일 보는 것들인데 정확히 어떤 구조인지 한번 짚어봤다.

요청(Request)

GET /api/users HTTP/1.1
Host: api.example.com
Authorization: Bearer eyJhbGci...
Content-Type: application/json

응답(Response)

HTTP/1.1 200 OK
Content-Type: application/json
Cache-Control: max-age=3600

{ "users": [...] }

상태 코드

코드의미언제 나오냐면
200성공일반 조회
201생성됨POST로 리소스 만들었을 때
204내용 없음DELETE 성공, 응답 바디 없을 때
301영구 이동도메인 변경, SEO에도 영향 있음
304변경 없음캐시 유효해서 서버가 바디 안 보낼 때
400잘못된 요청파라미터 누락이나 형식 오류
401인증 필요로그인 안 됨
403권한 없음로그인은 됐는데 접근 불가
404없음리소스 없음
500서버 오류백엔드 문제

401이랑 403을 혼동하면 FE에서 분기 처리할 때 애매해진다는 걸 협업하면서 느꼈다. 백엔드에서 정확히 구분해서 내려줘야 하는 이유가 있었던 거다.

HTTP 버전별 차이

면접 단골 주제라 정리해뒀다.

HTTP/1.1  요청을 하나씩 순서대로 처리.
          이미지 10개면 10번 기다려야 함. (Head-of-line blocking)

HTTP/2    하나의 연결에서 여러 요청을 동시에 처리. (멀티플렉싱)
          이미지 10개 병렬로 받을 수 있고 헤더도 압축.

HTTP/3    UDP 기반으로 바뀌어서 연결 속도가 더 빠름.
          아직 모든 환경에서 지원하진 않음.

Next.js 같은 프레임워크가 번들을 잘게 쪼개도 괜찮은 이유가 HTTP/2 덕분이라는 것도 이번에 알게 됐다.

면접 답변 정리

Q. HTTP와 HTTPS의 차이는?

HTTP는 데이터를 평문으로 전송하고, HTTPS는 TLS를 통해 암호화해서 전송한다. HTTPS는 인증서로 서버 신뢰성을 검증하고 중간자 공격을 방지한다. 쿠키 Secure 속성이나 브라우저 보안 API가 HTTPS에서만 동작하기 때문에 배포 환경에서는 필수다.

Q. HTTP/1.1과 HTTP/2의 차이는?

HTTP/1.1은 요청을 순차 처리해서 앞 요청이 지연되면 뒤도 막힌다. HTTP/2는 멀티플렉싱으로 하나의 연결에서 여러 요청을 병렬 처리하고 헤더도 압축해서 성능이 크게 개선됐다.
